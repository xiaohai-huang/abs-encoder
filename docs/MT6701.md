# MT6701 Datasheet Excerpt
## Hall Based Angle Position Encoder Sensor

### 7.8.2 SSI Read Angle

This section describes the Serial Synchronous Interface (SSI) protocol used to read angle data from the MT6701 sensor.

#### 📊 SSI Data Format (Figure-25)

The SSI communication protocol allows the master controller to retrieve angle, status, and error-checking data from the sensor. The data frame consists of **24 bits** total, transmitted sequentially.


**Signal Definitions:**
*   **CSN (Chip Select):** Active-low signal. Data transfer initiates when CSN is pulled to logic `Low`.
*   **CLK (Clock):** Serial port clock controlled by the SSI master. It idles `High`.
*   **DO (Data Output):** Serial data line driven by the MT6701.
    *   **Timing:** Data is driven on the **rising edge** of CLK and must be captured by the master on the **falling edge** of CLK.

A data transfer starts when CSN is pulled to logic 'Low' . The MT6701 transfers data on the rising edge of CLK, and the data transfer finally stops when CSN is pulled to logic 'High'.

**Data Frame Structure:**
The 24-bit data stream is divided into three segments. Note that while the diagram labels cycles 1–24, the bit indices below correspond to the register map (0–23).

| Bit Index | Field Name | Width | Description |
| :--- | :--- | :--- | :--- |
| **0 – 13** | **Angle Data** | 14-bit | Raw absolute angle value $D[13:0]$. Transmitted MSB first ($D13 \rightarrow D0$). |
| **14 – 17** | **Status** | 4-bit | Magnetic field status flags $Mg[3:0]$. |
| **18 – 23** | **CRC** | 6-bit | Cyclic Redundancy Check code $CRC[5:0]$ for data integrity. |

---

#### 📐 Angle Calculation

The 0~360° absolute angle $\theta$ is calculated using the 14-bit Angle Data $D[13:0]$ extracted from the SSI frame.

**Formula:**
$$ \theta = \frac{\sum_{i=0}^{13} (D[i] \cdot 2^i)}{16384} \cdot 360^{\circ} $$

*Where:*
*   $D[i]$ is the value of the $i$-th bit.
*   $16384$ is $2^{14}$ (the total resolution of the 14-bit data).

---

#### ⚠️ Magnetic Field Status (Mg[3:0])

The 4-bit status field provides diagnostic information regarding the magnet's condition.

| Bit(s) | Value | Status Description |
| :--- | :--- | :--- |
| **Mg[1:0]** | `0` | **Normal** |
| | `1` | Magnetic Field is too Strong |
| | `2` | Magnetic Field is too Weak |
| | `3` | *Reserved / Undefined* |
| **Mg[2]** | `0` | **Normal** |
| | `1` | Push Button is Detected |
| **Mg[3]** | `0` | **Normal** |
| | `1` | Loss of Track |

---

#### 🔒 CRC Verification

The CRC is used to verify the integrity of the received data.

*   **Data Range:** The CRC covers the 18-bit payload consisting of Angle Data $D[13:0]$ and Status $Mg[3:0]$.
    *   **MSB:** $D[13]$
    *   **LSB:** $Mg[0]$
*   **Polynomial:** $X^6 + X + 1$
*   **Transmission Order:** MSB is streamed in first.

> **Note:** the datasheet does **not** state the CRC initial value or final
> XOR. The firmware assumes init `0`, no final XOR. On real hardware the
> acceptance test is binary: every frame validates, or no frame does.

#### ⏱️ SSI Timing Parameters (Figure-24)

| Symbol | Parameter | Min | Typ | Max | Unit |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **TH** | Time between CSN falling edge and CLK rising edge | 100 | — | — | ns |
| **TCLK** | Clock period | 64 | — | — | ns |
| **TCLKL** | Low period of clock | 30 | — | — | ns |
| **TCLKH** | High period of clock | 30 | — | — | ns |
| **TL** | Time between CLK last falling edge and CSN rising edge | 0.5·TCLK | — | — | ns |
| **TR / TF** | Rise / fall time of digital signal (20 pF load) | — | 10 | — | ns |
| **TDV** | Data valid time of DO (20 pF load) | — | — | 15 | ns |

Implications for an SPI master (the relevant three):

*   **Max SCLK ≈ 15.6 MHz** (`1 / TCLK`). The CubeMX SPI1 config of
    4.5 Mbit/s (APB2 72 MHz ÷ 16) has 3.5× margin.
*   **TH ≥ 100 ns** between CSN low and the first SCLK edge — satisfied by
    HAL's setup time at 4.5 Mbit/s.
*   **TL ≥ 0.5·TCLK** — keep CSN low for at least half a clock after the
    last SCLK edge before releasing it.

#### 🧩 SPI Bring-up Notes

*   **Clock polarity / phase.** The datasheet draws CLK idling **high** and
    says DO is driven on the rising edge and captured on the falling edge —
    read literally that is SPI **mode 2** (CPOL=High, CPHA=1st edge).
    However, all working reference drivers sample half a period *after* the
    drive edge using SPI **mode 1** (CPOL=Low, CPHA=2nd edge), which is the
    phase relationship that keeps the first bit aligned without an extra
    clock. **Keep mode 1 (the current SPI1 config);** if first hardware
    reads come out shifted/garbage, try mode 2 — it is a CubeMX-only
    change, no firmware changes needed.
*   **SSI is one-directional.** The master clocks 24 bits with CSN held
    low and reads DO (MISO); MOSI is not used by the chip (send dummy
    bytes). The firmware reads 3 bytes per frame.
*   **Bus topology (this board: 4 encoders, 2 SPI buses).** Two SPI
    masters, two encoders each. SCK and MISO are shared per bus, each
    encoder has its own CSN; MOSI is not used by the chips (the master
    sends dummy bytes). Only one CSN may be low at a time — with two
    slaves selected on a shared bus, both drive MISO simultaneously.

    | Bus | SCLK speed | SCK | MISO | MOSI | Encoder | CSN (STM32 pin) |
    | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
    | SPI1 (APB2) | ÷16 → 4.5 Mbit/s | PA5 | PA6 | PA7 (NC) | 1 | CSN1 (PA3) |
    | | | | | | 2 | CSN2 (PA4) |
    | SPI2 (APB1) | ÷8 → 4.5 Mbit/s | PB13 | PB14 | PB15 (NC) | 3 | CSN3 (PA9) |
    | | | | | | 4 | CSN4 (PA8) |

*   **Per-encoder wiring (MT6701 SOP-8):** pin 6 (A) → that bus's MISO,
    pin 7 (B) → that bus's SCK, pin 8 (Z) → the encoder's own CSN pin,
    pin 1 (VDD) → 3.3 V (0.1 µF decoupling per chip), pin 4 (GND) → GND,
    pin 2 (MODE) → VDD (or float — internal 200 kΩ pull-up), pins 3 (OUT)
    and 5 (PUSH) → NC. QFN-16 equivalents: A=6, B=7, CSN=8, MODE=14,
    OUT=15, VDD=13, GND=16.
*   **Magnet per encoder:** Ø6 mm × 2.5 mm diametrically magnetized, gap
    0.5–2 mm over the sensing center.
